\section{\unclass Executive Summary}

\unclass This document reports the results of Verification and Validation (V\&V) activities conducted on the T-150/TRV-150 Heavy-Lift UAS AFSIM Plugin Suite v2.0, performed in accordance with DoDI 5000.61 [1] and MIL-STD-3022 [2].

\unclass The Plugin Suite comprises five AFSIM plugins totaling 7,736 lines of C++ source across 26 files. The plugins model flight dynamics (6DOF mover), battery discharge and voltage sag, electric propulsion with thermal modeling, Vortex Ring State detection, and slung load dynamics for a coaxial octocopter UAS.

\unclass \textbf{V\&V activities completed:}
\begin{itemize}
    \item \unclass \textbf{Verification}: Code review of all 26 source files; plugin registration pattern validation; build verification on Linux (GCC 13.3) and Windows (MSVC); static analysis of numerical integration methods.
    \item \unclass \textbf{Validation}: Execution of 16 formal test cases across four test families; flight pattern energy analysis across five patterns; comparison to manufacturer specifications and analytic predictions.
\end{itemize}

\unclass \textbf{Summary of results:}
\begin{itemize}
    \item \unclass All 10 formal Phase 1 test cases (TF01, TF02) passed their acceptability criteria.
    \item \unclass All 6 validation suite test cases (TF03, TF04) demonstrated expected behavior consistent with physics predictions.
    \item \unclass Three defects were discovered and corrected during V\&V testing (motor efficiency calibration, SOC initialization, build script error).
    \item \unclass Energy conservation was validated to within 0.01\% error.
    \item \unclass Flight endurance of 14.3~minutes was measured against a 36-minute manufacturer specification; the gap is attributed to conservative auxiliary power and rotor coefficient assumptions.
\end{itemize}

\unclass \textbf{Overall assessment}: The T-150 UAS AFSIM Plugin Suite v2.0 is suitable for its intended use in intelligence analysis with the limitations documented in Section 4.

\section{\unclass Problem Statement}

\unclass The T-150/TRV-150 is a heavy-lift coaxial octocopter UAS designed for autonomous cargo delivery and logistics resupply. Intelligence community analysts require a simulation capability to assess operational performance, flight envelope, and vulnerability characteristics. Specific analytical questions include:

\begin{enumerate}
    \item \unclass What are the operational range and endurance limitations under various payload and mission profile configurations?
    \item \unclass How does flight pattern efficiency affect energy consumption and mission planning?
    \item \unclass What flight regimes create vulnerability conditions (VRS, low battery, thermal limits, slung load instability)?
    \item \unclass What detection signatures characterize this platform class for counter-UAS assessments?
    \item \unclass How do payload mass and slung load dynamics affect flight stability and performance?
\end{enumerate}

\unclass No existing AFSIM model provides engineering-level subsystem modeling for heavy-lift coaxial multirotor UAS platforms. The T-150 Plugin Suite was developed to fill this gap.

\subsection{\unclass Validation Results}

\subsubsection{\unclass Test Family 01: 6DOF Physics (5 Tests -- ALL PASS)}

\unclass \textbf{TC-01: Motor Step Response (30~s)} -- \PASS. Motor dynamics functional with first-order lag ($\tau$ = 0.15~s). Steady-state hover power $\approx$20~kW for 68~kg empty mass. No oscillation or overshoot.

\unclass \textbf{TC-02: Attitude Recovery (60~s)} -- \PASS. After sharp turns, platform returned to level flight within 2--3~seconds. No sustained oscillations. Damping consistent with PD controller gains.

\unclass \textbf{TC-03: Position Hold (120~s)} -- \PASS. Exceptional stability. Velocity drift on the order of 1e-17~m/s, effectively zero. Altitude maintained within $\pm$0.5~m.

\unclass \textbf{TC-04: Velocity Step (60~s)} -- \PASS. Achieved 14.49~m/s against 15~m/s target ($<$1~m/s error). Power consumption correctly increased during acceleration.

\unclass \textbf{TC-05: Extreme Maneuvers (120~s)} -- \PASS. No NaN, infinity, or divergent values. Maximum tilt 25$^\circ$. Integrator remained stable under rapid attitude commands.

\subsubsection{\unclass Test Family 02: Battery/Power System (5 Tests -- ALL PASS)}

\unclass \textbf{TC-06: Voltage Sag (300~s)} -- \PASS (after bug fix). After correcting SOC initialization bug, voltage sag model produces expected Li-Ion discharge profile. Internal resistance exhibits U-shaped SOC dependency.

\unclass \textbf{TC-07: Ground Effect (120~s)} -- \PASS. Smooth descent profile. Power decreased in ground effect zone. Cheeseman-Bennett model produced continuous thrust augmentation up to 1.3x.

\unclass \textbf{TC-08: Coaxial Efficiency (60~s)} -- \PASS. Mechanical power output 19.5--20.1~kW during hover. Coaxial efficiency factor of 0.85 correctly applied.

\unclass \textbf{TC-09: Energy Conservation (300~s)} -- \PASS. Energy balance error $<$0.01\%. SOC decreased monotonically and linearly during constant-power hover.

\unclass \textbf{TC-10: Endurance (858~s)} -- \PASS. Flight time 14.3~minutes (858~s) from 100\% SOC to cutoff. All warning thresholds triggered correctly: low battery at 20\% SOC, critical at 10\% SOC, voltage sag warning below 42.0~V.

\subsubsection{\unclass Test Family 03: VRS Detection (3 Tests from Validation Suite)}

\unclass \textbf{TC-VRS-01: Slow Descent (2~m/s)} -- VRS\_STATE = CLEAR (state 0). Descent rate 50\% of threshold. VRS margin remained above 0.8. No warnings raised.

\unclass \textbf{TC-VRS-02: Medium Descent (4~m/s)} -- VRS\_STATE = CAUTION (state 1). VRS margin dropped to $\approx$0.5, correctly triggering CAUTION. VRS\_CAUTION flag set.

\unclass \textbf{TC-VRS-03: Fast Descent with Forward Speed (6~m/s descent, 8~m/s forward)} -- VRS\_STATE = CLEAR (state 0). Forward speed exceeds 5.0~m/s immunity threshold, preventing VRS despite 150\% descent rate. Correctly demonstrates forward flight VRS immunity.

\subsubsection{\unclass Test Family 04: Slung Load Dynamics (3 Tests from Validation Suite)}

\unclass \textbf{TC-SL-01: Short Cable (3~m), Light Load (10~kg)} -- Stable maneuvers with small oscillations. Natural frequency consistent with $f_n$ = 0.288~Hz (3.5~s period). Swing angles remained below 20$^\circ$ threshold.

\unclass \textbf{TC-SL-02: Medium Cable (5~m), Medium Load (25~kg)} -- Turn-induced oscillations within bounds. Natural frequency consistent with $f_n$ = 0.223~Hz (4.5~s period). Swing magnitude within 18$^\circ$ threshold.

\unclass \textbf{TC-SL-03: Long Cable (10~m), Heavy Load (50~kg)} -- Longer period oscillations as expected. Natural frequency consistent with $f_n$ = 0.157~Hz (6.4~s period). Cable tension below 5,000~N limit.

\subsection{\unclass Defects Found and Fixed During V\&V}

\unclass \textbf{Defect 1: Motor Efficiency Calibration.} Motor efficiency was set to 0.37 (37\%) instead of 0.85 (85\%). Electrical power draw was $\approx$2.3x the mechanical requirement. Endurance improved $\approx$110\% after fix.

\unclass \textbf{Defect 2: SOC Initialization.} \texttt{mEnergyConsumed} not initialized for non-100\% starting SOC. Fixed by initializing to \texttt{(1.0 - mInitialSOC) * mBatteryCapacityWh}.

\unclass \textbf{Defect 3: Build Script.} Arithmetic expression \texttt{((COPIED\_COUNT++))} evaluated to zero (falsy) with \texttt{set -e}, causing premature exit. Fixed by using assignment form.

\section{\unclass V\&V Recommendations}

\subsection{\unclass Suitability for Intended Use}

\unclass The T-150 UAS AFSIM Plugin Suite v2.0 is \textbf{suitable for its intended use} in intelligence analysis, mission planning analysis, counter-UAS assessment, and vulnerability analysis, subject to the limitations in Section 4.3.

\subsection{\unclass Recommended Usage Constraints}

\begin{enumerate}
    \item \unclass \textbf{Endurance scaling}: Absolute endurance predictions (14.3~minutes measured) should not be directly compared to manufacturer specifications (36~minutes) without applying a calibration factor. Relative comparisons between mission profiles remain valid.
    \item \unclass \textbf{Wind conditions}: All results assume calm wind. Real-world operations in wind will degrade range and endurance.
    \item \unclass \textbf{Platform adaptation}: Applying the model to other multirotor platforms requires updating motor, battery, and airframe parameters per the UAM adaptation guidance.
\end{enumerate}

\subsection{\unclass Recommended Model Improvements}

\begin{enumerate}
    \item \unclass Additional rotor coefficient calibration using manufacturer motor test data
    \item \unclass Auxiliary power refinement (current 4~kW constant may overestimate)
    \item \unclass Wind model integration for operational realism
    \item \unclass Battery thermal coupling for extreme temperature operations
    \item \unclass Independent V\&V by a separate organization for higher accreditation confidence
\end{enumerate}

\section{\unclass V\&V Lessons Learned}

\subsection{\unclass Development Process Observations}

\begin{enumerate}
    \item \unclass \textbf{AI-assisted development produced architecturally sound code but required human oversight for calibration.} The motor efficiency parameter was set to 37\% instead of 85\%, a calibration error not detectable by structural code review alone.
    \item \unclass \textbf{Motor efficiency was the single largest calibration issue.} The difference between 37\% and 85\% produced a 110\% change in flight endurance.
    \item \unclass \textbf{Semi-implicit Euler integration proved numerically robust} even under extreme inputs including 25$^\circ$ tilt angles and rapid throttle transients.
\end{enumerate}

\subsection{\unclass Architecture Observations}

\begin{enumerate}[start=4]
    \item \unclass \textbf{AuxData loose coupling enabled independent plugin testing.} Each plugin could be tested with or without others present, with graceful fallback to default values.
    \item \unclass \textbf{Plugin registration pattern required careful attention} to AFSIM-specific conventions. The two-level registration pattern is not intuitive.
\end{enumerate}

\subsection{\unclass Testing Process Observations}

\begin{enumerate}[start=6]
    \item \unclass \textbf{Dedicated test scenarios with controlled inputs were more valuable} than complex multi-objective scenarios for pass/fail determination.
    \item \unclass \textbf{CSV telemetry logging was essential} for post-test analysis of energy conservation, voltage profiles, and power consumption.
    \item \unclass \textbf{Build script testing should be included in V\&V scope.} The \texttt{((COPIED\_COUNT++))} defect was a non-obvious Bash/\texttt{set -e} interaction.
\end{enumerate}
