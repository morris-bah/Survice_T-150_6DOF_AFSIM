\section{\unclass Requirements Verification Traceability Matrix}\label{RTM}  

\guidance{
	
	\unclass TIMELINE: Test plan should be near final draft (all tests planned out with behavior tested at a minimum) for PDR for review by NGIC and finalized by CDR.
	
	\unclass The test plan consists of the test framework and the linking of test cases to requirements.  Most requirements require testing and thus have an associated KPIs; some requirements can be confirmed by sbservation. 
		
	\unclass The table below should include all of the requirements and corresponding tests which will demonstrate that the requirement is met. The test coverage column should include "ST1" for system family test one. If a unit test covers that, then use "unit test" in that column with a unit test identifier. If unit tests are used to verify a requirement, then a section should be included in the TDD that describes it/them.  
	
	\unclass Test results/status will be updated for \gls{trr} and should include the following options as the text:
	
	\unclass Pass – The test case ran successfully as written \newline
	\unclass Pass with C – Although a particular test step failed, the test case will be marked as pass with caveat because the deficiencies do not substantially impair the required  performance. \gls{ngic} \gls{tpoc} should be notified immediately if this is the expect result to gain concurrence. \newline
	\unclass Fail – Unable to complete the test or a requirement could not be verified \newline
	\unclass Pending – Step failed but needs analysis, after which, disposition is changed as identified above. This is only an option while in development for incremental updates at milestones. By \gls{fdr}, its should be one of the above options. \newline
}
