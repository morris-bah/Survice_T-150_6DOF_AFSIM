## 1. Plugin Discovery and Loading

### Plugin Directories

AFSIM loads plugins from **two directories** - both must contain the plugin for reliable loading:

| Directory | Purpose | Naming Convention |
|-----------|---------|-------------------|
| `$AFSIM_DIR/lib/wsf_plugins/` | WSF framework plugins (primary) | `plugin_name.so` (no lib prefix) |
| `$AFSIM_DIR/bin/mission_plugins/` | Mission executable plugins | `libplugin_name.so` (lib prefix required) |

**Critical**: If your plugin is in only one directory, it may not load depending on how AFSIM is invoked.

### Discovery Order

1. AFSIM scans `lib/wsf_plugins/` for `.so` files
2. AFSIM scans `bin/mission_plugins/` for `.so` files
3. For each `.so` file, AFSIM attempts to load it and call `WsfPluginVersion()`
4. If version check passes, AFSIM calls `WsfPluginSetup()`

### Version Compatibility

AFSIM validates plugin ABI compatibility by checking:
- `WSF_PLUGIN_API_MAJOR_VERSION` - Must match exactly
- `WSF_PLUGIN_API_MINOR_VERSION` - Must be compatible
- `WSF_PLUGIN_API_SYSTEMABI_STRING` - Platform/compiler ABI

**Symptom of ABI mismatch**: Plugin loads but immediately causes segfault or type registration fails silently.

## 2. Required C-Linkage Entry Points

Every AFSIM plugin **must** export two functions with C linkage:

```cpp
#include "plugin_name_export.h"  // Generated by CMake's generate_export_header()
#include <iostream>

// Include AFSIM headers
#include "WsfPlugin.hpp"
#include "WsfApplication.hpp"
#include "WsfApplicationExtension.hpp"

extern "C"
{
    // 1. VERSION CHECK - Called first, validates ABI compatibility
    PLUGIN_NAME_EXPORT void WsfPluginVersion(UtPluginVersion& aVersion)
    {
        aVersion = UtPluginVersion(
            WSF_PLUGIN_API_MAJOR_VERSION,
            WSF_PLUGIN_API_MINOR_VERSION,
            WSF_PLUGIN_API_SYSTEMABI_STRING
        );
    }

    // 2. SETUP - Called once after version check passes
    PLUGIN_NAME_EXPORT void WsfPluginSetup(WsfApplication& aApplication)
    {
        if (!aApplication.ExtensionIsRegistered("your_unique_extension_id"))
        {
            aApplication.RegisterFeature("your_feature_name");
            aApplication.RegisterExtension(
                "your_unique_extension_id",
                std::make_unique<WsfDefaultApplicationExtension<YourRegistrationClass>>()
            );
        }
    }
}
```

### Export Macros

CMake generates export headers via `generate_export_header()`:

```cmake
# In CMakeLists.txt
include(GenerateExportHeader)
generate_export_header(${PLUGIN_NAME}
    EXPORT_FILE_NAME ${CMAKE_CURRENT_BINARY_DIR}/${PLUGIN_NAME}_export.h
)
```

This creates macros like `PLUGIN_NAME_EXPORT` for Windows DLL export/Linux visibility.

### Debug Verification

Add a global constructor to verify the `.so` file is actually loaded:

```cpp
namespace
{
    struct PluginLoadVerifier
    {
        PluginLoadVerifier()
        {
            std::cout << "[PLUGIN_NAME] ===== .SO FILE LOADED (global constructor) =====" << std::endl;
        }
    };
    static PluginLoadVerifier sVerifier;
}
```

If this message doesn't appear, the wrong `.so` file is being loaded (see [Common Issues](#7-common-issues-and-debugging)).

## 3. Two-Level Registration Pattern

AFSIM uses a two-level registration pattern:

### Level 1: Application Extension (Plugin Load Time)

When AFSIM loads your plugin, `WsfPluginSetup()` registers an **application extension**:

```cpp
// In WsfPluginSetup():
aApplication.RegisterExtension(
    "my_plugin_registration",
    std::make_unique<WsfDefaultApplicationExtension<MyRegistration>>()
);
```

### Level 2: Scenario Extension (Scenario Load Time)

Your registration class inherits from `WsfScenarioExtension` and registers types when a scenario loads:

```cpp
// MyRegistration.hpp
class MyRegistration : public WsfScenarioExtension
{
public:
    void AddedToScenario() override
    {
        WsfScenario& scen = GetScenario();

        // For Processors:
        WsfProcessorTypes::Get(scen).AddCoreType(
            "MY_PROCESSOR_TYPE",
            std::make_unique<MyProcessor>(scen)
        );

        // For Movers:
        WsfMoverTypes::Get(scen).AddCoreType(
            "MY_MOVER_TYPE",
            std::make_unique<MyMover>(scen)
        );
    }

    void SimulationCreated(WsfSimulation& aSim) override
    {
        // Optional: simulation-level hooks
    }
};
```

### Alternative: Custom Application Extension

For more control, create a custom application extension:

```cpp
class MyApplicationExtension : public WsfApplicationExtension
{
public:
    void ScenarioCreated(WsfScenario& aScenario) override
    {
        aScenario.RegisterExtension(
            "my_scenario_extension",
            std::make_unique<MyRegistration>()
        );
    }
};

// Then in WsfPluginSetup():
aApplication.RegisterExtension("my_app_extension",
    std::make_unique<MyApplicationExtension>());
```

## 4. Plugin Naming Conventions

### Library Naming

| Location | Expected Format | Example |
|----------|-----------------|---------|
| Build output (`lib/`) | `lib<name>.so` | `libt150_battery.so` |
| `wsf_plugins/` | `<name>.so` | `t150_battery.so` |
| `mission_plugins/` | `lib<name>.so` | `libt150_battery.so` |

### Type Registration Names

Plugin types should follow AFSIM conventions:

| Type | Convention | Example |
|------|------------|---------|
| Processor | `<PREFIX>_<NAME>_PROCESSOR` | `T150_BATTERY_PROCESSOR` |
| Mover | `WSF_<NAME>_MOVER` | `WSF_ROTORCRAFT_6DOF_MOVER` |
| Sensor | `<PREFIX>_<NAME>_SENSOR` | `T150_LIDAR_SENSOR` |

### Class ID Methods

Provide static methods for type IDs:

```cpp
class MyProcessor : public WsfProcessor
{
public:
    static const char* GetMyProcessorClassId()
    {
        return "MY_PROCESSOR_TYPE";
    }

    const char* GetScriptClassName() const override
    {
        return GetMyProcessorClassId();
    }
};
```

## 5. Environment Setup

### Required Environment Variables

| Variable | Purpose | Example |
|----------|---------|---------|
| `AFSIM_ROOT` or `AFSIM_DIR` | AFSIM installation path | `/opt/afsim2.2505` |
| `DISPLAY` | Required for GUI tools (WSL) | `:0` |

### AFSIM Auto-Detection

The build scripts search for AFSIM in order:
1. `$AFSIM_ROOT` environment variable
2. `$AFSIM_DIR` environment variable
3. `/opt/afsim*` (glob)
4. `/usr/local/afsim*`
5. `~/.afsim*`

### WSL-Specific Setup

For graphical tools in WSL:
```bash
# Set display for X11 forwarding
export DISPLAY=:0

# Run visualization
DISPLAY=:0 /opt/afsim2.2505/bin/mystic output/scenario.aer
```

Headless execution (no DISPLAY needed):
```bash
/opt/afsim2.2505/bin/mission scenarios/scenario.afsim
```

## 6. Build and Installation Workflow

### Standard Workflow

```bash
# 1. Navigate to project root
cd /path/to/project

# 2. Build plugins (auto-detects AFSIM)
./ngic_afsim_build.sh

# 3. Install to AFSIM (requires sudo)
sudo ./ngic_afsim_install.sh

# 4. Run scenario to test
/opt/afsim2.2505/bin/mission scenarios/test_scenario.afsim
```

### CMake Direct Build

```bash
# Configure
cmake -B plugins/build \
      -S plugins \
      -DCMAKE_BUILD_TYPE=Release \
      -DCMAKE_PREFIX_PATH="/opt/afsim2.2505"

# Build
cmake --build plugins/build --parallel

# Install (if CMake install targets configured)
sudo cmake --install plugins/build --prefix /opt/afsim2.2505
```

### Manual Installation

```bash
# Copy to both plugin directories
sudo cp lib/libmyplugin.so /opt/afsim2.2505/lib/wsf_plugins/myplugin.so
sudo cp lib/libmyplugin.so /opt/afsim2.2505/bin/mission_plugins/libmyplugin.so
sudo chmod 755 /opt/afsim2.2505/lib/wsf_plugins/myplugin.so
sudo chmod 755 /opt/afsim2.2505/bin/mission_plugins/libmyplugin.so
```

## 7. Common Issues and Debugging

### Issue 1: Old Plugin Files Persisting

**Symptom**: Debug output you added never appears; behavior doesn't match code changes.

**Cause**: Multiple versions of the plugin exist in different locations.

**Diagnosis**:
```bash
# Find all instances of your plugin
find /opt/afsim* -name "*battery*.so" 2>/dev/null
find /home -name "*battery*.so" 2>/dev/null
ls -la lib/

# Check timestamps
ls -la /opt/afsim2.2505/lib/wsf_plugins/*battery*
ls -la /opt/afsim2.2505/bin/mission_plugins/*battery*
```

**Fix**:
```bash
# Remove old versions
sudo rm /opt/afsim2.2505/lib/wsf_plugins/t150_battery.so
sudo rm /opt/afsim2.2505/bin/mission_plugins/libt150_battery.so

# Clean local lib/ of old naming variants
rm lib/t150_battery.so  # if lib-prefixed version exists

# Reinstall
sudo ./ngic_afsim_install.sh
```

### Issue 2: Plugin Loads But Type Not Found

**Symptom**: AFSIM runs but reports "Unknown type: MY_PROCESSOR_TYPE"

**Causes**:
1. Scenario extension not registering the type
2. Registration class `AddedToScenario()` not called
3. Wrong type name string

**Diagnosis**:
```cpp
// Add debug output to registration
void AddedToScenario() override
{
    std::cout << "[MYPLUGIN] AddedToScenario() called!" << std::endl;
    std::cout << "[MYPLUGIN] Registering type: " << MyProcessor::GetClassId() << std::endl;
    // ... registration code
}
```

### Issue 3: String Parameters Include Quotes

**Symptom**: AuxData key lookups fail; string comparisons fail.

**Cause**: AFSIM's `ReadValue()` for strings includes the surrounding quotes from the scenario file.

**Example**:
```
# Scenario file:
power_source_key "6dof_total_power"

# ReadValue result:
mPowerSourceKey = "\"6dof_total_power\""  // Quotes included!
```

**Fix**:
```cpp
aInput.ReadValue(mPowerSourceKey);
// Strip surrounding quotes if present
if (mPowerSourceKey.size() >= 2 &&
    mPowerSourceKey.front() == '"' && mPowerSourceKey.back() == '"')
{
    mPowerSourceKey = mPowerSourceKey.substr(1, mPowerSourceKey.size() - 2);
}
```

### Issue 4: ABI Mismatch / Segfault on Load

**Symptom**: Plugin causes crash immediately on load, or loads but types don't work.

**Cause**: Plugin compiled against different AFSIM version than runtime.

**Diagnosis**:
```bash
# Check AFSIM version
/opt/afsim2.2505/bin/mission --version

# Verify CMake found correct AFSIM
grep -r "AFSIM_ROOT" plugins/build/CMakeCache.txt
```

**Fix**: Rebuild plugin against the correct AFSIM installation:
```bash
rm -rf plugins/build
AFSIM_ROOT=/correct/path ./ngic_afsim_build.sh
```

### Issue 5: Plugin Not in Both Directories

**Symptom**: Plugin works with `warlock` but not `mission`, or vice versa.

**Cause**: Plugin only installed to one of the two plugin directories.

**Fix**: Use `ngic_afsim_install.sh` which installs to both locations, or manually copy to both:
- `$AFSIM_DIR/lib/wsf_plugins/` (name without lib prefix)
- `$AFSIM_DIR/bin/mission_plugins/` (name with lib prefix)

### Debug Commands Reference

```bash
# Check what plugins AFSIM loads
/opt/afsim2.2505/bin/mission scenario.afsim 2>&1 | grep -i "plugin"

# Verify your debug output appears
/opt/afsim2.2505/bin/mission scenario.afsim 2>&1 | grep "[MYPLUGIN]"

# Check library dependencies
ldd lib/libmyplugin.so

# Verify symbols are exported
nm -D lib/libmyplugin.so | grep WsfPlugin

# Compare installed vs local
md5sum lib/libmyplugin.so
md5sum /opt/afsim2.2505/lib/wsf_plugins/myplugin.so
```

## 8. Quick Reference

### Minimum Plugin Structure

```
my_plugin/
├── CMakeLists.txt
└── source/
    ├── MyProcessor.hpp
    ├── MyProcessor.cpp
    ├── MyRegistration.hpp
    └── MyPluginRegistration.cpp
```

### CMakeLists.txt Template

```cmake
cmake_minimum_required(VERSION 3.16)
set(PLUGIN_NAME my_plugin)

# Find AFSIM
find_package(afsim REQUIRED)

# Sources
file(GLOB PLUGIN_SOURCES source/*.cpp)

# Build shared library
add_library(${PLUGIN_NAME} SHARED ${PLUGIN_SOURCES})

# Generate export header
include(GenerateExportHeader)
generate_export_header(${PLUGIN_NAME}
    EXPORT_FILE_NAME ${CMAKE_CURRENT_BINARY_DIR}/${PLUGIN_NAME}_export.h
)

# Include directories
target_include_directories(${PLUGIN_NAME} PUBLIC
    ${CMAKE_CURRENT_SOURCE_DIR}/source
    ${CMAKE_CURRENT_BINARY_DIR}
)

# Link AFSIM
target_link_libraries(${PLUGIN_NAME} AFSIM::wsf)

# Properties
set_target_properties(${PLUGIN_NAME} PROPERTIES
    POSITION_INDEPENDENT_CODE ON
    PREFIX "lib"  # Ensure lib prefix for output
)
```

### Registration File Template

```cpp
// MyPluginRegistration.cpp
#include "my_plugin_export.h"
#include "MyRegistration.hpp"

#include "WsfPlugin.hpp"
#include "WsfApplication.hpp"
#include "WsfApplicationExtension.hpp"

extern "C"
{
    MY_PLUGIN_EXPORT void WsfPluginVersion(UtPluginVersion& aVersion)
    {
        aVersion = UtPluginVersion(
            WSF_PLUGIN_API_MAJOR_VERSION,
            WSF_PLUGIN_API_MINOR_VERSION,
            WSF_PLUGIN_API_SYSTEMABI_STRING
        );
    }

    MY_PLUGIN_EXPORT void WsfPluginSetup(WsfApplication& aApplication)
    {
        if (!aApplication.ExtensionIsRegistered("my_plugin_registration"))
        {
            aApplication.RegisterFeature("my_plugin");
            aApplication.RegisterExtension(
                "my_plugin_registration",
                std::make_unique<WsfDefaultApplicationExtension<MyRegistration>>()
            );
        }
    }
}
```

### Installation Checklist

- [ ] Plugin built successfully (`lib/libmyplugin.so` exists)
- [ ] Plugin copied to `$AFSIM_DIR/lib/wsf_plugins/myplugin.so`
- [ ] Plugin copied to `$AFSIM_DIR/bin/mission_plugins/libmyplugin.so`
- [ ] No old versions in either directory (check timestamps)
- [ ] No old versions in local `lib/` directory
- [ ] MD5 checksums match between source and installed
- [ ] Debug output appears when running scenario
